## What shipped

Every map is original and embedded; no private packs remain.

- **Main server,** Springdale Central on UDP 7777 (directory ID
  `dellcon-north-spine`). Rotation: CTF, then Capture & Hold, then Team
  Deathmatch.
- **Football server,** Springdale Football on UDP 7778 (`[{"playlist":"football"}]`).
  It self-registers with the directory as `play-peakrunner-net-7778`.
- **Server self-registration:** servers with `PEAKRUNNER_DIRECTORY_URL` and
  `PEAKRUNNER_ADVERTISE_URL` POST to `https://dir.peakrunner.net/announce`
  every 20 s. The directory lists a server only when:
  - its host resolves to the caller's IP (Cloudflare's client IP header in
    tunnel mode), and
  - a certificate-validated status query to that address succeeds.

  Limits: entries lapse after 65 s without an announce, one announce per
  address every 4 s, at most 4 servers per address and 32 in total.
- **Gameplay:** loadouts, football, Team Deathmatch with random conditions,
  Ozarktic Blast, Reefbreak, the loot packs and the fumble fix (see
  AGENTS.md and `docs/`).

## Verification

- **Tests and checks:** workspace library tests, the all-target and WASM
  checks, the app-boundary check, the connected rotation test, the Reefbreak
  Python tests (10) and a byte-identical Reefbreak rebuild.
- **Server image:** tested in isolation on dellcon with both rotations;
  healthy at about 29 MiB idle.
- **Live servers:** both healthy after the switch, which happened with 0
  players.
  - The main server reports the new version and protocol through the
    directory.
  - WAN QUIC smoke tests with 2 clients:
    - 7777, 10 s: PASS, max snapshot gap 103 ms.
    - 7778, 35 s, past football's 20 s warmup: PASS, 102 ms.
  - Idle VPS usage: 40 MiB and 38 MiB. With 2 clients the football server
    used about 15% of the single CPU, leaving about 500 MB free.
- **Directory:** lists both servers. The football server self-registered
  and was verified.
- **Feeds:** all three signed public feeds pass `launcher-release
  check-public`. Manifests are served with `Cache-Control: no-store`.
- **Downloads:** all six advertised archives match their hashes over HTTPS,
  and apex and www serve the new release manifest.
- **Mac:** the packaged standalone app passes `codesign --verify --deep
  --strict` and launches. The managed build installed from the signed feed
  launches with its external map.

## Not verified

- Windows runtime: cross-built only.
- Linux launch, GPU and audio: built on Debian 12 but not launched this
  time.
- Human balance and traversal of the new maps and modes.
- Bot flag play: the headless report shows no flag grabs on any map.
- Two full 8-player matches at once on the 1-CPU VPS: not measured, and
  likely CPU-bound. A bigger host (for example a 4-core dedicated server)
  is the upgrade path.

## Rollback

Recheck occupancy first. Then:

1. **VPS:** restore `compose.yaml`, `release.conf` and `source.json` from
   the backup directory. The previous image `sha256:d801944b...` is still
   loaded, but it needs the old private-map mount, which is also still in
   place. Remove the football service, then `sudo -n docker compose
   --env-file release.conf up -d --no-deps match` and stop `football`.
2. **dellcon:** restore `compose.yaml`, then recreate `site` and
   `directory` with the dummy-token `--no-deps --no-build` command.
3. **Launcher:** sign a new higher-sequence feed pointing at the previous
   payloads. Restoring the old manifests fails downgrade protection.
